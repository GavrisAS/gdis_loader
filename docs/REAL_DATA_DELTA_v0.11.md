# Агрегированный delta report для итерации v0.11

Реальные источники не включены в этот документ. Сравнение сделано с кодом baseline `dd6a409` / v0.10. Показатели по фонду ниже пересчитаны для тех же 109 строк Берегового, чтобы отделить изменение scope от изменения identity. `calculation_date` нового прогона: локальная дата операции `2026-10-01`.

## Фонд и scope

| Исходный фонд всех участков | 129 | 129 |

Eligibility рассчитано отдельно по подтвержденным категориям; строки всех категорий Берегового сохранены. 25 переходов в ambiguity вызваны тем, что root-only фондовые обозначения нельзя однозначно привязать к lifecycle GDI identity по истории/точности даты. Для них сохранена fund identity и выдана provenance-rich диагностика; значения GDI/LHA не подставляются. Синтетических дат и suffix collapse нет.

Калькулятор сейчас обрабатывает 100 строк на остальных расчетных листах; `tblData` расширена на 109 target rows и выдано capacity warning.

## Well history и identity

- Прочитано 123 записи листа `БЛУ`.
- Прочитано 69 GTM/event blocks: 55 ЗБС, 8 ПВЛГ, 5 ПВР и 1 прочее.
- Непустые даты: 3 точных DAY и 187 MONTH; YEAR и invalid date среди распознанных непустых дат на `БЛУ` — 0. День для MONTH не создавался.
- Модель/test cases подтверждают: `051 -> 51`, `051_ЗБС -> 51_ЗБС`, `054_ПВЛГ -> 54_ПВЛГ`, `10403 != 10403_МЗС`; общий физический корень сохранен только как lineage key. Суффикс `ЗБС2` сохраняется, но не интерпретируется как номер события.
- Для ЗБС/ПВЛГ при неполной точности или нескольких последовательных однотипных границ resolver не выбирает событие случайно. ПВР/КЛК остаются событиями, не lifecycle boundary.

В Береговом scope распознано 1832 строки `Вид исследования`: 33 `ID`, 866 `ID_KVD`, 695 `KVD`, 209 `EXCLUDED`, 29 `UNKNOWN`. Unknown types не входят в выбор GDI; для них есть INFO с provenance. Эти классы не задают дополнительную валидность исследования.

## LHA: сравнение тех же 109 строк фонда

| Доступность значения (current или previous) | v0.10 | Новая реализация |
|---|---:|---:|
| Cl | 89 | 76 |
| ВГФ | 87 | 77 |
| Нет ни Cl, ни ВГФ | 20 | 32 |

На 84 строках, которые остаются однозначно сопоставленными, хотя бы одна метрика доступна в обеих версиях для 77 строк; без обеих метрик остаются 7. Среди 25 новых ambiguous строк baseline ранее имел LHA для 12 строк (Cl — 12, ВГФ — 11); эти значения теперь пусты из-за неразрешённой lifecycle assignment. Поэтому все 12 дополнительных строк без ЛХА объясняются именно блокировкой неоднозначных связей.

Среди 84 однозначных строк по отдельным метрикам: Cl availability изменилась 77 -> 76 (2 потери, 1 приобретение); ВГФ — 76 -> 77 (1 приобретение, потерь нет). На выбранных целевых точках разрешено максимум 201 duplicate metric/timestamp group. Baseline выдавал 4 `LHA_DUPLICATE_TIMESTAMP_CONFLICT` предупреждения для текущего scope; новая версия не выдаёт этот warning code, а записывает INFO `LHA_DUPLICATE_TIMESTAMP_RESOLVED_MAX` с ячейками всех дублей и выбранной ячейкой.

Точное число заполненных целевых LHA ячеек после update: Cl current 76, Cl previous 75, ВГФ current 77, ВГФ previous 75.

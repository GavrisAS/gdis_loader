# Архитектура gdis_loader

## Цель

Отделить ETL/идентификацию скважин от Excel-калькулятора. Калькулятор остается расчетным шаблоном, загрузчик отвечает только за подготовку и запись входных данных.

## Поток данных

```text
Фонд скважин ─┐
ГДИ ──────────┼─> Readers -> Normalization -> Well matching -> Transforms -> Validation
ЛХА ──────────┤                                                        |
Суточный рапорт┘ (schema validation; values reserved for future debit rule) v
                                                         Data-sheet writer
                                                                |
                                                                v
                                                    копия калькулятора .xlsx
```

## Слои

### readers

Чтение конкретных форматов файлов. На этом уровне нет бизнес-решений по рейтингованию.

### domain

Типы данных: скважина фонда, запись ГДИ, запись ЛХА, результат сопоставления, строка целевого листа, diagnostic issue.

### matching

Консервативное разрешение физической скважины и актуального ствола/пласта. Любая неоднозначность становится явным результатом, а не случайным выбором.

### transforms

Получение целевых колонок только после успешного сопоставления и только по утвержденным правилам.

### validation

Проверка схем источников, обязательных заголовков, типов дат/значений, дубликатов и целевой книги.

### excel

Запись исключительно листа `Данные`. Writer обязан минимизировать изменения OOXML-пакета.
Структура и заголовки читаются через `openpyxl`, затем исходный ZIP-пакет
копируется и минимально патчится стандартным XML-парсером. Меняются только
XML листа `Данные` и связанная с ним `tblData`; это позволяет сохранить
`calcChain`, shared strings, расширения и нетаргетные листы без round-trip
через `openpyxl`.

### gui

PySide6-Essentials (`QtWidgets`/`QtCore`). Выбор файлов, сохранение путей,
запуск фоновой задачи через `QThread`/worker `QObject` и отображение результата.
Виджеты не вызываются из worker-потока; бизнес-логика отсутствует.

Lifecycle worker привязан к конкретному экземпляру `QThread`: обработчики
результата и ошибки обновляют статус, но оставляют окно занятым до `finished`
этого thread. Устаревший thread не может очистить ссылки новой операции.

### LHA conflict handling

`LhaIndex` группирует каждую метрику по различным `measured_at`, независимо для
Cl и ВГФ. Дубликаты с одинаковым числом схлопываются. Различные числа в один
момент дают `LHA_DUPLICATE_TIMESTAMP_CONFLICT` только для выбираемой точки
`current` или `previous`: конфликтная текущая точка оставляет обе целевые
ячейки пустыми, а конфликтная предыдущая не заменяется более старой точкой.
Более старые конфликты не попадают в WARNING diagnostics. Сообщение содержит
скважину, пласт, метрику, роль, timestamp, количество и компактный список
различных значений. Агрегация среднего/минимума/последней строки запрещена.

Ожидаемые пропуски и Excel error tokens в числовых ячейках ЛХА/суточного
рапорта считаются missing. Они не создают per-cell WARNING; reader может
добавить одну INFO-сводку, а содержательный произвольный текст сохраняется как
INFO заметка. `0` остаётся валидным числом.

### Minimal writer patch

Перед записью writer получает диапазон `tblData` из table XML. Он заменяет
только data rows внутри старого диапазона, сохраняет строки вне таблицы и
завершает update с `TARGET_TABLE_EXPANSION_CONFLICT`, если расширение пересекает
нетабличный контент. Точно совпадающее условное форматирование `A7:A<old>` на
листе `Данные` расширяется вместе с таблицей. Остальные ZIP entries копируются
byte-identical; исходные root namespace declarations, включая `x14ac`,
восстанавливаются после сериализации XML.

### service / cli

`service.py` — единый application service для GUI и CLI: валидация, readers,
индексы, matching, построение `TargetRow`, безопасная запись и JSON-report.
CLI нужен для CI и воспроизводимой диагностики без mainloop.

## Конфигурация

`config.toml` хранит только пользовательские пути и UI-состояние. Бизнес-правила не должны незаметно жить в пользовательском config.

## Выходной файл

По умолчанию исходный калькулятор не перезаписывается. Создается новый `.xlsx`.

## Платформенность

Вся бизнес-логика должна одинаково работать на Linux и Windows. Windows-специфична только финальная сборка PyInstaller и smoke-тест дистрибутива.

## Производительность источников

ГДИ и ЛХА читаются один раз в `read_only/data_only` режиме с шириной,
ограниченной найденными заголовками. Для листа ЛХА учитывается, что Excel
может объявлять миллион строк из-за форматирования: после 2000 пустых строк
идентификационных колонок чтение прекращается. Индексы GDI/LHA строятся в
памяти и используются для всех строк фонда без повторного чтения исходников.

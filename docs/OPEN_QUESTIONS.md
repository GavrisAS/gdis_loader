# Вопросы заказчику / владельцу данных

## Источник истины

Для `gdis_loader` решения принимаются только на основании:

1. `GDIS_Rating_Calculator_FIXED.xlsx` — текущая реализация калькулятора;
2. `README.txt` — описание актуальных источников и правил привязки;
3. текущих файлов исходных данных:
   - `Фонд 2026 на 01.08.2026.xlsx`;
   - `Сводная таблица ГДИ.xlsx`;
   - `База ЛХА_Итог!.xlsm`;
   - `07.2026 Cуточный рапорт БГП_полный.xlsm`.

Презентации, старые версии калькулятора, отчеты и другие справочные материалы
не используются для принятия бизнес-решений, пока пользователь явно не попросит
обратное.

Не закрывать перечисленные ниже вопросы предположениями.

---

## A. Приоритетные вопросы — нужны для полей текущего калькулятора и активных критериев

### 1. Состояние скважины

Как категории актуального фонда должны преобразовываться в поле `Состояние`
листа `Данные`?

В фонде есть:

- `дающие газ`;
- `остановленные в отчетном месяце`;
- `бездействующие текущего года`;
- `бездействующие прошлых лет`.

В примере калькулятора встречаются, в частности:

- `В работе`;
- `В бездействии`;
- `Ожидает запуск`.

Нужно утвердить точное соответствие категорий фонда значениям калькулятора.

### 2. Дата расчета / дата отсечения

Какую дату использовать как дату расчета для временных показателей:

- дату актуального листа фонда;
- дату из `C1` фонда;
- системную дату запуска загрузчика;
- другую дату?

Это влияет как минимум на:

- `Продолжительность без ГДИ`;
- `Не проведен АДД`;
- `Удельное количество ГДИ`;
- потенциально другие временные поля.

### 3. Дата запуска

Из какого из приложенных источников должна заполняться `Дата запуска`?

Если в текущем комплекте источника нет, нужно указать дополнительный файл/лист
или правило вычисления.

Также нужно определить, что именно считается датой запуска для актуальной строки
скважины.

### 4. Какие записи считать ГДИ

В `Сводная таблица ГДИ.xlsx` есть поле `Вид исследования`.

Нужно определить:

- какие значения `Вид исследования` входят в `Количество ГДИ`;
- учитывать ли всю доступную историю или только часть истории актуальной
  конфигурации скважины;
- как обрабатывать комбинированные виды исследований.

Это правило также требуется для `Продолжительность без ГДИ` и
`Удельное количество ГДИ`.

### 5. Недостаточно ГДИС

Текущий калькулятор ожидает готовое поле `Недостаточно ГДИС` со значением
`Да/Нет`.

Нужно определить:

- из какого источника брать этот признак; либо
- по какому точному правилу загрузчик должен его вычислять.

Не выводить правило из старых методик или презентаций.

### 6. ГТМ

Активный критерий калькулятора использует поле `ГТМ` (`Да/Нет`) и называется
`Запланировано или проведено ГТМ`.

В `Сводная таблица ГДИ.xlsx` имеется `Дата проведения ГТМ`, но источника
планируемых ГТМ в текущем комплекте однозначно не определено.

Нужно уточнить:

- считать ли достаточным наличие фактической `Дата проведения ГТМ`;
- за какой период проведенное ГТМ должно давать `Да`;
- откуда брать планируемые ГТМ.

### 7. Снижение продуктивности

Как заполнять `Снижение продуктивности`:

- из готового списка/признака;
- или рассчитывать из исходных показателей?

Если рассчитывать, нужны точные поля, формула, период сравнения и пороги.

### 8. Рост хлора

В ЛХА уже доступны `Cl текущий` и `Cl предыдущий`, но текущий калькулятор
ожидает отдельное поле `Рост хлора` (`Да/Нет`).

Нужно определить точное правило:

- любое `Cl текущий > Cl предыдущий`;
- абсолютный порог;
- относительный рост;
- иной алгоритм.

Также нужно определить поведение при отсутствии одной из двух точек или при
конфликтном timestamp.

### 9. Проблемы ГДМ

Активный критерий использует поле `Проблемы ГДМ`.

В приложенных текущих источниках однозначного поля/листа с этим признаком не
выявлено.

Нужно указать:

- источник данных;
- либо подтвердить, что это отдельный вручную предоставляемый список.

### 10. ЛНД

В `Сводная таблица ГДИ.xlsx` присутствуют:

- `Выход на РФП (да/нет)`;
- `Достоверность согласно ЛНД`.

Калькулятор ожидает одно поле `ЛНД` (`Да/Нет`) для критерия
`Невыход на радиальный режим / низкая достоверность ЛНД`.

Нужно утвердить точную таблицу преобразования реальных исходных значений в
`Да/Нет`, включая пустые, смешанные и нестандартные текстовые значения.

### 11. АДД

Для полей:

- `Последний АДД`;
- `Не проведен АДД`

в текущем комплекте источников однозначный источник не определен.

Нужно указать:

- где хранится дата АДД;
- какие записи считать АДД;
- от какой даты считать скользящий год.

### 12. Продолжительность без ГДИ

Нужно определить точную формулу:

- единица измерения;
- дата последнего ГДИ;
- дата отсечения;
- поведение, если ГДИ отсутствуют полностью.

### 13. Удельное количество ГДИ

Калькулятор ожидает уже рассчитанное числовое поле.

Нужно утвердить:

- точную формулу;
- какую дату считать началом периода работы;
- какую дату считать концом периода;
- какое количество исследований использовать;
- что делать при нулевом количестве ГДИ.

## C. Вопросы качества и идентификации текущих исходных данных

### 19. Маркер `МЗС`

В актуальной истории ГДИ встречается обозначение `МЗС`, и как минимум одна
скважина текущего фонда сопоставляется с записью такого вида.

Нужно подтвердить, что `МЗС` является вариантом обозначения той же физической
скважины и числовая часть может использоваться как `base_well_id`.

`ГС` отдельно подтверждать не требуется: исходный `README.txt` прямо указывает,
что в базе ЛХА признак `ГС` может отсутствовать в номере и связь должна
восстанавливаться по номеру, пласту и дате.

### 20. Несколько значений ЛХА на один timestamp

В `База ЛХА_Итог!.xlsm` встречаются разные значения Cl/ВГФ с одинаковыми
датой и временем.

Текущий loader намеренно:

- не выбирает строку по ее физическому порядку;
- не усредняет значения;
- оставляет конфликтную current/previous точку пустой;
- формирует `LHA_DUPLICATE_TIMESTAMP_CONFLICT`.

Если такие точки требуется заполнять, нужно предоставить правило разрешения
конфликта.

### 21. Строка фонда `153 162`

В актуальном фонде обнаружено значение `153 162` без разделителя.

Текущий loader трактует его как две скважины `153` и `162`, что позволяет
согласовать контрольное количество элементов.

Нужно подтвердить, что это действительно пропущенная запятая, а не единый
идентификатор.

## Уже закрытые вопросы / не включать в OPEN_QUESTIONS

### Колонка J фонда

Закрыто.

`README.txt` задает фонд рейтингования как действующий + бездействующий.
Поэтому `в освоении / ожидании освоения` из колонки J не входит в мастер-список
рейтингования.

Это ожидаемое правило, а не warning/error.

### Расчетная емкость 100 строк

Это техническое ограничение текущего калькулятора, а не вопрос заказчику.
Хранить в техническом backlog/README.

### Суффикс `R`

В текущем актуальном фонде не является блокирующей неоднозначностью.
Возвращаться к вопросу только при появлении реального ambiguous match.

### Составные пластовые записи

Текущий real-data прогон дает `AMBIGUOUS=0`.
Не формулировать общий бизнес-вопрос заранее; поднимать конкретный вопрос только
при появлении неоднозначной актуальной записи.

### Manual μ

Поле явно является ручным. Загрузчик не должен заполнять его без отдельного
требования.

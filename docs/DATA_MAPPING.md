# Маппинг листа `Данные`

## Scope и правила

Текущий target scope — **Береговое ЛУ**. В таблицу не добавляется колонка ЛУ. Все категории фонда Берегового сохраняются в target rows; eligibility считается отдельно (`дающие`, `дающие газ`, `остановленные в отчетном периоде`), но строки по этому признаку пока не фильтруются.

Подтвержденные customer decisions подробно описаны в [`CUSTOMER_DECISIONS.md`](CUSTOMER_DECISIONS.md); неразрешенные вопросы — в [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md). Readers находят столбцы по заголовкам.

## Поля

| Поле `Данные` | Статус | Источник / правило |
|---|---|---|
| Скважина | заполняется | Актуальное обозначение однозначно сопоставленной записи ГДИ; suffix входит в target identity. Если fund содержит только root, suffix-кандидат допускается только через подтвержденную историю/дату. |

| Недостаточно ГДИС | заблокировано | Количественное правило известно, но valid-GDI definition уточняется. |

| Cl текущий / предыдущий | заполняются | Текущая/предыдущая точка по timestamp после collapse duplicate timestamps max; только same field, plast и однозначная lifecycle assignment. `0` сохраняется. |
| Проблемы ГДМ | заблокировано | Нет подтвержденного правила. |
| ЛНД | условно | `Да` при reliability `Низкая` ИЛИ RFP `нет`; `Нет`, если оба значения распознаны и условия ложны; иначе blank + `LND_SOURCE_INCOMPLETE`. |

## Идентичность и lifecycle matching

`base_well_id` — физический корень только для поиска lineage. `target_well_id` сохраняет ведущий-ноль-нормализованный номер и весь suffix (`51`, `51_ЗБС`, `54_ПВЛГ`, `10403_МЗС`). GDI matching сначала требует exact target identity. Для fund без suffix допускается suffix-вариант только при подтвержденном event/date/plast assignment из well history. LHA row без suffix допускается лишь при совпадении месторождения, пласта и timestamp с тем же подтвержденным stage. Иначе поле остается пустым/ambiguous.
